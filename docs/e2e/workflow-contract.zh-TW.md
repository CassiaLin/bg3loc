# E2E-01A | 處理流程規則 (Workflow Contract)

[English](workflow-contract.md)

```text
Milestone: End-to-End Translation Workflow 01A
State: ACCEPTED
Implementation: not started
Core reopening: no
Accepted basis: documentation / current implementation conformance review
```

## 1. 設計規則

這個工具的運作方式取決於您做的兩個主要選擇。您可以隨意混搭它們！

### 情境深度 (Evidence Profile：您想看多少遊戲情境？)

```text
basic
context
full
```

這控制了工具在您翻譯時，會為您收集並顯示多少額外的背景資訊。

### 翻譯策略 (Translation Strategy：您想看舊翻譯嗎？)

```text
standard
blind-first
```

這控制了您在開始翻譯時，是否能看到現有的遊戲文字。

⚠️ **請記住：** 這是兩個完全獨立的選擇。舉例來說：
- `basic` + `standard`：您只獲得最少的情境資訊，但能看到舊的翻譯。
- `context` + `blind-first`：您能獲得一些情境，但一開始看不到舊的翻譯。
- `full` + `blind-first`：您能獲得最完整的情境資訊，但同樣是在沒看過舊文字的情況下進行翻譯。

選擇 `full`（完整）不代表「這是一個繁體中文專案」，而選擇 `blind-first`（盲翻優先）也不代表您會自動獲得「完整」的情境資訊！

---

## 2. 公開階段圖表

以下是您翻譯遊戲時將會採取的確切步驟順序。

```text
Project configuration (專案設定)
        ↓
Discovery (探索)
        ↓
Locale extraction (語言提取)
        ↓
Evidence preparation (情境準備)
        ↓
Translation package build (翻譯素材包建置)
        ↓
External translation (外部翻譯)
        ↓
Review / QA (審查與品管)
        ↓
Final translation validation (最終翻譯驗證)
        ↓
Rebuild (重建)
        ↓
Install dry-run (安裝演習)
        ↓
Install (安裝)
```

工具會在背景自動幫您處理大部分的步驟。

---

## 3. 階段規則

以下是每個步驟實際上在做什麼。

### 3.1 專案設定 (Project configuration)

**它的作用：** 儲存您的選擇！它會記住您使用的語言、您選擇的情境深度與策略，以及您的檔案放在哪裡。
**它寫入了什麼：** 只寫入它自己的設定檔。
**它「絕對不會」做的事：** 它永遠不會去動遊戲檔案。

---

### 3.2 探索 (Discovery)

幕後執行的指令：
```text
bg3loc scan
```

**它的作用：** 使用第三方解包工具來查看您的《柏德之門 3》資料夾，並精確找出您安裝的遊戲版本。它會找到遊戲的壓縮包裝檔（`.pak`）。
**它「絕對不會」做的事：** 它永遠不會修改遊戲。

---

### 3.3 語言提取 (Locale extraction)

幕後執行的指令：
```text
bg3loc extract
```

**它的作用：** 把遊戲的語言檔（`.loca`）從遊戲中抽出來並整理好。它會利用 `ContentUid`（每筆遊戲文字的身分證號碼）來分類它們。
**它「絕對不會」做的事：** 它永遠不會修改遊戲。它也絕對不會強迫您使用額外的參考語言。

---

### 3.4 情境準備 (Evidence preparation)

這會根據您選擇的**情境深度**而有所不同。

#### basic (基本)
提供最基本的需求。您會得到要翻譯的文字以及必要的安全規則，但沒有深入的研究檔案。

#### context (情境)
提供您有用的背景資訊，例如是誰在說話、他們正在進行什麼任務，以及前後的對話內容。它讓事情保持簡單明瞭。

#### full (完整)
啟動重型機具。它會抽出我們能找到關於該段文字的每一筆進階研究資料。

**它「絕對不會」做的事：** 這些選項全都不會碰到您的遊戲檔案。

---

## 4. 翻譯素材包建置 (Translation package build)

幕後執行的指令：
```text
bg3loc build
```

這個步驟會建立出您將要實際打開並編輯的試算表檔案。

### Standard (標準) 策略
如果您選擇了 `standard`，您的試算表會在英文旁邊同時顯示目前的遊戲翻譯。

### Blind-first (盲翻優先) 策略
如果您選擇了 `blind-first`，工具會主動向您隱藏目前的翻譯。在您完成第一遍的翻譯之前，您都不會看到它。

**它「絕對不會」做的事：** 工具會幫您準備好檔案，但它不會幫您翻譯文字。

---

## 5. 處理流程指令界線

流程中設有一個硬性停止點：

```text
workflow prepare (流程準備)
→ 產出翻譯素材包
→ 您在外部進行翻譯 (等待)
→ workflow validate (流程驗證)
→ 依照設定進行審查 / QA 驗證
→ rebuild (重建)
→ install (安裝)
```

當您執行 `workflow prepare` 後，工具會把檔案給您，然後停止運作。它會耐心等待您實際把翻譯內容打進檔案裡。
您必須在完成翻譯文字輸入後，才去執行 `workflow validate`。

---

## 6. 外部翻譯界線

**您**可以自己決定翻譯實際上要如何進行。
您可以自己打字、使用 AI，或是用網站來管理團隊。這個工具不在乎！它只會利用 `ContentUid` 來檢查最終結果。

---

## 7. 審查與品管 (Review / QA)

有兩種完全不同的方式來檢查您的工作。

### 7.1 結構與語意情境審查
這會檢查您的翻譯在遊戲中是否合理。例如，您有沒有正確翻譯介面按鈕？您有沒有搞砸任務描述？

### 7.2 專案語言 QA
這會檢查您有沒有遵守自己的拼字規則（例如特定的台灣用語習慣）。您必須自己提供這些規則檔！如果工具發現有違反規則的地方，它會標記出來讓您查看。這不代表您錯了，它只是希望您再確認一次。

---

## 8. 最終翻譯驗證 (Final translation validation)

幕後執行的指令：
```text
bg3loc validate
```

在讓您把文字放進遊戲之前，工具會檢查：
- 您有沒有不小心重複了某個 `ContentUid`？
- 您有沒有不小心破壞了遊戲內部的程式碼語法？
- 您是不是真的把所有該翻譯的東西都翻譯完了？

如果通過了，您就能進入下一個步驟。

---

## 9. 重建 (Rebuild)

幕後執行的指令：
```text
bg3loc rebuild
```

工具會拿走您完成的試算表，並把它重新打包成《柏德之門 3》看得懂的 `.loca`（遊戲語言檔）格式。

---

## 10. 安裝 (Installation)

幕後執行的指令：
```text
bg3loc install
```

這是**唯一**會修改您遊戲檔案的步驟。
您必須先進行一次演習：
```text
install --dry-run
→ install
```
它會在套用您的新翻譯之前，先備份您原本的遊戲檔案。

## 13. 狀態與失效

工具會記住您目前進行到哪一個步驟：
```text
not-started (未開始)
ready (準備就緒)
running (執行中)
completed (已完成)
invalidated (已失效)
failed (失敗)
```
如果遊戲更新了，或是您更改了核心檔案，工具會發現資料過期了，並將它們標記為「已失效 (invalidated)」，讓您知道必須重新執行準備流程。

---

## 14. 失敗界線

如果指令失敗了，它會確切告訴您是哪一個步驟壞了。它不會默默地試圖修復，然後塞給您一個壞掉的檔案。如果檔案遺失或是安全檢查沒通過，它會立刻停止。

---

## 15. 工作區所有權

您產生的所有文字都會留在您電腦裡的專屬資料夾中。
遊戲官方且受版權保護的文字，絕對不會被上傳到我們的公開原始碼庫裡。

---

這些簡單的新指令，並沒有取代掉那些複雜的舊指令。進階使用者如果需要進行高度特殊的操作，依然可以使用那些底層的指令！
