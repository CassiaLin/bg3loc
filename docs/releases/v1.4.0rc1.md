# BG3Loc 1.4.0rc1 — Local release candidate notes

[繁體中文](v1.4.0rc1.zh-TW.md)

**UNRELEASED.** This is a local RC candidate, with no official tag, GitHub Release or PyPI publication. Version and engineering checks do not authorize deployment, game writes or Production Activation. See the [Windows Basic guide](../getting-started.md).

## First-version scope

Windows Basic uses the player's own BG3 installation and a separately installed LSLib/Divine backend. Use a small scope of actual source UIDs, a single operator and stable original Extract/baseline paths:

1. Install the tool and backend; create a Basic project and prepare materials.
2. Translate manually or externally. Return generated XLSX/JSONL rows without changing immutable source/identity fields or runtime syntax.
3. Validate, rebuild LOCA and, when the target container requires it, PAK.
4. Run `workflow install` without `--apply` for a fresh Dry-run. Stop on any failure.

Technical QA does not prove semantic quality or game loading. Dry-run changes project evidence only; it neither writes game files nor grants Apply/Rollback permission. Low-level `install` defaults to apply and is not a fallback for a blocked workflow.

Package/runtime version is `1.4.0rc1`. Newly generated research manifests use producer stamp `bg3loc-1.4.0rc1`; their request IDs, ordering, prompt bytes and request-package fingerprints retain their contracts. Existing research outputs and historical acceptance records are not rewritten.

## Compatibility and recovery

Old Basic workspaces without the required Receipt fail closed; no automatic backfill or edited-return migration. Preserve old returns, fresh Scan/Extract/Prepare/Validate for current game files, then manually rebase suitable translations by UID/source/version. Editing returns requires new Validate → Rebuild → Dry-run. History paths alone never confer current install eligibility.

Workspace/DB schemas, Stage 0 contracts, Receipt version, H0/HSE identity and prompt algorithms remain unchanged. The package release number is a separate version axis.

## Excluded and deferred capabilities

Production/automatic Provider workflows, B1-02 activation, Legacy Production Finalize and advanced context/full research are outside first Windows Basic acceptance. **A7 implementation remains DEFERRED and its Legacy portability/concurrency defects remain unremediated.** B1-03 stays default OFF with production transport blocked; retaining its code is not activation or general dialogue safety validation. Native Linux/macOS, detached portability, concurrent operators and whole-corpus throughput are not certified.
